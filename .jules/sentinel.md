## 2024-03-01 - CSP Configuration for Babel Standalone Applications
**Vulnerability:** Missing Content Security Policy (CSP) headers in applications dynamically loading code and resources, leading to potential Cross-Site Scripting (XSS) and data exfiltration.
**Learning:** When configuring CSP for standalone Babel applications (`babel-standalone`), `'unsafe-inline'` and `'unsafe-eval'` are strictly required in the `script-src` directive for the code to transpile and execute correctly in the browser. Attempting to lock these down will completely break the application logic. Furthermore, applications relying on external CDNs for images and videos must explicitly whitelist those sources in `img-src` and `connect-src` directives; otherwise, a restrictive `default-src` will block the app's core functionalities.
**Prevention:** Always implement a baseline CSP in HTML files (`<meta http-equiv="Content-Security-Policy">`). Carefully audit external domains used for fonts, scripts, and media. For Babel standalone, recognize the explicit need for `'unsafe-inline'` and `'unsafe-eval'`. Test CSP thoroughly in the browser console, as violations will be clearly reported there and can easily break functionality without causing server-side errors.
