## 2026-05-19 - Content Security Policy (CSP) with Standalone Babel
**Vulnerability:** The application lacked a Content Security Policy (CSP), making it potentially vulnerable to Cross-Site Scripting (XSS) and data injection attacks by allowing resources to be loaded from any external domain.
**Learning:** Implementing a strict CSP is crucial. However, because this application utilizes standalone Babel for client-side transpilation, the `'unsafe-inline'` and `'unsafe-eval'` directives are absolutely required in the `script-src` policy for the application to function. A restrictive `default-src` without these directives breaks the app. Additionally, domains like `cdnjs.cloudflare.com`, `image.pollinations.ai`, `pixabay.com`, etc., must be explicitly whitelisted.
**Prevention:** Future implementations should avoid client-side transpilation in production if a fully strict CSP (without `unsafe-eval`) is required. If standalone Babel must be used, always explicitly whitelist required CDNs and APIs rather than relying on an open policy or accidentally breaking the app with overly restrictive defaults.
