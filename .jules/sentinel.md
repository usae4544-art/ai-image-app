## 2024-03-24 - Add Content Security Policy (CSP)
**Vulnerability:** The application lacks a Content Security Policy (CSP), leaving it vulnerable to Cross-Site Scripting (XSS), data injection attacks, and potentially unexpected inclusion of external scripts or assets. Since the app heavily relies on external services via specific domains for styling, scripts, and content, there is no restriction on where data can be loaded from or submitted to.
**Learning:** Because this is a client-side React app using Babel standalone, the CSP requires 'unsafe-inline' and 'unsafe-eval' for scripts to execute properly. Furthermore, since images and videos are dynamically fetched from several external domains (e.g., `image.pollinations.ai`, `pixabay.com`), explicit whitelisting via `img-src` and `media-src` is necessary rather than relying on `default-src` or just `connect-src`.
**Prevention:** Always implement a baseline Content Security Policy that restricts resource loading to specifically required origins, using `default-src 'self'` as a starting point and explicitly defining other directives (`script-src`, `style-src`, `img-src`, `media-src`, `connect-src`, `font-src`) to minimize the attack surface.
