## 2024-05-18 - Missing Content Security Policy in Babel Standalone Application
**Vulnerability:** The application entirely lacked a Content Security Policy (CSP), defaulting to allowing any external resource (scripts, images, media, connections) to be loaded and executed. This significantly increases the risk and potential impact of Cross-Site Scripting (XSS) and data exfiltration.
**Learning:** Implementing CSP for applications using Babel standalone requires allowing `unsafe-inline` and `unsafe-eval` in `script-src` because Babel compiles and evaluates code dynamically in the browser. Furthermore, specific directives like `media-src`, `img-src`, and `connect-src` must be explicitly defined to allow core functionality (images/videos from external sources) while preventing fallback to a restrictive `default-src`.
**Prevention:** Always implement a strict CSP by default on all web applications. When using client-side transpilers like Babel standalone, explicitly document and allow the necessary 'unsafe' directives, but heavily restrict all other resource domains to only those strictly required by the application.
