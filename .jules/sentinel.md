## 2024-06-06 - Implement Content Security Policy for Babel Standalone Application
**Vulnerability:** Missing Content Security Policy (CSP), making the application susceptible to Cross-Site Scripting (XSS) and other data injection attacks. Without a CSP, the browser has no restrictions on the origins from which scripts, images, or media can be loaded.
**Learning:** This repository utilizes Babel standalone for client-side React transpilation, which dynamically executes code in the browser. Consequently, a restrictive `script-src` breaks core functionality; `unsafe-inline` and `unsafe-eval` are mandatory for this architecture. Furthermore, failing to explicitly whitelist media domains (e.g., `image.pollinations.ai`, `pixabay.com`) in `img-src` and `media-src` results in a fallback to a restrictive `default-src`, blocking the application's core image and video generation features.
**Prevention:** Implement a tailored CSP that strictly whitelists necessary external domains (`cdnjs.cloudflare.com`, `fonts.googleapis.com`, etc.) and media sources, while accepting the required `unsafe-*` directives for Babel. Ensure comprehensive testing of all external resource loading paths when adjusting CSP.
