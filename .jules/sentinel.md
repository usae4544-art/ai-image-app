## 2024-10-24 - Missing Content Security Policy and Reverse Tabnabbing
**Vulnerability:** The application was missing a Content Security Policy (CSP), making it completely vulnerable to Cross-Site Scripting (XSS) and malicious iframe embedding (Clickjacking). Additionally, `window.open` calls opening external generated image links were using `_blank` without `noopener,noreferrer`, leading to Reverse Tabnabbing vulnerabilities where the newly opened tab could gain reference to and manipulate the parent `window.opener`.
**Learning:** Pure client-side applications built with standalone Babel still require robust HTTP equivalent meta tags to enforce modern browser security boundaries, especially when dynamically constructing prompts and passing user data into external URLs. It is easy to overlook Reverse Tabnabbing when quickly adding download buttons.
**Prevention:** Always implement a strict, default-deny CSP for client-only applications, using `meta` tags if HTTP headers aren't available, and ensure any external link opening mechanism (like `window.open(url, "_blank")`) explicitly drops the opener reference by appending `"noopener,noreferrer"`.
