## 2024-03-24 - Content Security Policy (CSP) for Standalone Babel Apps
**Vulnerability:** Missing Content Security Policy (CSP) headers leaving the application vulnerable to Cross-Site Scripting (XSS) and unwanted resource injection.
**Learning:** In a completely frontend, serverless environment relying on Babel standalone and inline React components (`type="text/babel"`), strict CSP configurations often break the application. 'unsafe-inline' and 'unsafe-eval' must be included in the `script-src` directive for Babel to transpile code in the browser dynamically. Additionally, relying solely on `default-src` is risky; explicit declarations for external resources (e.g., `media-src` for video and `img-src` for specific AI providers) are required to prevent fallback blocking of core features.
**Prevention:** Implement CSP via meta tags for standalone files. Explicitly whitelist required CDNs (`cdnjs.cloudflare.com`), font providers (`fonts.googleapis.com`, `fonts.gstatic.com`), and media APIs. Document the necessity of `unsafe-eval` and `unsafe-inline` specifically for development/Babel setups so future developers don't accidentally remove them and break the application.
