## 2024-06-12 - [Content Security Policy (CSP) for Standalone Babel Application]
**Vulnerability:** The application was lacking a Content Security Policy (CSP), leaving it vulnerable to Cross-Site Scripting (XSS) and other data injection attacks.
**Learning:** Implementing a restrictive CSP in an application that relies on client-side Babel transpilation requires specific configurations. Specifically, the `script-src` directive must include `'unsafe-inline'` and `'unsafe-eval'` for Babel to parse and execute the JSX scripts correctly. Furthermore, external media sources (like `image.pollinations.ai`, `pixabay.com`, `www.pexels.com`, and `www.videvo.net`) must be explicitly whitelisted in `img-src`, `media-src`, and `connect-src` directives to maintain functionality, while preventing arbitrary domains from loading content.
**Prevention:** Always define an explicit CSP and thoroughly test it with all third-party scripts, CDNs, and media sources required by the application. Understand the architectural trade-offs, such as the necessity of `'unsafe-eval'` when using Babel standalone, and consider pre-compiling assets in a build step if possible to allow for stricter policies.
