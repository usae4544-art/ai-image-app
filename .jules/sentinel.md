## 2024-05-05 - Missing Content Security Policy in Standalone React App
**Vulnerability:** The application was missing a Content Security Policy (CSP), making it vulnerable to Cross-Site Scripting (XSS) and unauthorized resource loading. The reverse tabnabbing vulnerability was also present in `window.open()` calls.
**Learning:** When configuring CSP for standalone React apps using Babel (`babel-standalone`), `'unsafe-inline'` and `'unsafe-eval'` are strictly necessary for the client-side transpilation and React execution to work. Additionally, domains for dynamically fetched media (`image.pollinations.ai`, `pixabay.com`, etc.) must be explicitly whitelisted in `img-src`, `connect-src`, and `media-src` directives to prevent them from falling back to a restrictive `default-src` and breaking core functionality.
**Prevention:** Implement a robust CSP tailored to the application's specific resource requirements (including Babel's needs for standalone setups) and consistently use `noopener,noreferrer` when opening external links in new tabs.
