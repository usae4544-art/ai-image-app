## 2024-03-24 - Missing Content Security Policy (CSP)
**Vulnerability:** The application was missing a Content-Security-Policy (CSP) header or meta tag. Given it's an AI image generation app parsing user prompts, the lack of CSP exposed it to potential Cross-Site Scripting (XSS) and unauthorized data transmission risks.
**Learning:** For static, client-side React applications using Babel standalone, CSP requires a delicate balance. Strict defaults must be defined while explicitly permitting `'unsafe-inline'` and `'unsafe-eval'` for React/Babel to function, alongside careful whitelisting of external APIs (like `image.pollinations.ai`), CDNs, and font services. Missing a single required source (like `media-src`) can break core functionality when falling back to a restrictive `default-src`.
**Prevention:** Always implement a baseline CSP in web applications. For static apps, use the `<meta http-equiv="Content-Security-Policy">` tag. When adding new external integrations (like video sources or image generation APIs), verify they are explicitly whitelisted in the CSP directives rather than opening up `default-src`.
