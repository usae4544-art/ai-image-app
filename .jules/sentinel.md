## 2024-06-25 - Missing Content Security Policy (CSP)
**Vulnerability:** The application was missing a Content Security Policy (CSP) header, leaving it vulnerable to various attacks, including Cross-Site Scripting (XSS) and data injection. Without a CSP, the browser assumes all scripts, styles, images, and other resources are safe to load and execute, even if they come from untrusted sources.
**Learning:** This single-page application heavily relies on client-side rendering with Babel standalone and external CDN dependencies for React, fonts, and external APIs for media search and generation. Without a CSP, if an attacker could inject a script or manipulate data sources, the browser would execute it. It is critical to restrict the sources from which resources can be loaded to prevent malicious activities.
**Prevention:** Always implement a strict Content Security Policy (CSP) via a `<meta>` tag or HTTP header in web applications. Explicitly whitelist required domains for scripts (`script-src`), styles (`style-src`), fonts (`font-src`), images (`img-src`), media (`media-src`), and API connections (`connect-src`). For applications requiring inline scripts or eval (like Babel standalone), use `'unsafe-inline'` and `'unsafe-eval'` judiciously, and strictly control the other directives to mitigate risks.
