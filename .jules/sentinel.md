## 2024-05-11 - [Security Header] Content Security Policy for Babel Standalone
**Vulnerability:** Missing Content Security Policy (CSP) and Reverse Tabnabbing. The application completely lacked a Content Security Policy, and links opened in new tabs without `noopener,noreferrer` leaving the application exposed to Reverse Tabnabbing.
**Learning:** For standalone Babel applications (client-side transpilation), the CSP `script-src` must explicitly include `'unsafe-inline'` and `'unsafe-eval'`. External resources like `https://cdnjs.cloudflare.com` and `https://fonts.googleapis.com` must also be explicitly whitelisted. The application was opening links via `window.open` without `noopener,noreferrer`.
**Prevention:** Ensure that all standalone HTML/Babel applications include a restrictive CSP that explicitly whitelists only necessary resources, and always use `"noopener,noreferrer"` as the third parameter to `window.open(url, '_blank')` or on `target="_blank"` anchor tags to prevent Reverse Tabnabbing.
