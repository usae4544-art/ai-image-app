## 2024-06-18 - Missing Content Security Policy (CSP)
**Vulnerability:** The application lacks a Content Security Policy (CSP), making it vulnerable to Cross-Site Scripting (XSS) and data injection attacks. If an attacker manages to inject malicious scripts, there are no browser-level restrictions preventing the scripts from executing, exfiltrating data, or modifying the page content.
**Learning:** For a standalone React application using client-side Babel transpilation, a CSP must be carefully configured. It needs to allow `unsafe-inline` and `unsafe-eval` for scripts to work properly while still restricting external domains to only those explicitly required by the app (e.g., cdnjs.cloudflare.com, fonts.googleapis.com, image.pollinations.ai, pixabay.com, www.pexels.com, www.videvo.net). This is a unique challenge as typical strict CSPs would break the Babel standalone setup.
**Prevention:** Always implement a baseline CSP in `index.html` for frontend applications, even if they are statically served. When using Babel standalone, document the necessity of `unsafe-inline` and `unsafe-eval` and enforce strict whitelisting for all other directives (fonts, images, media, connections) to provide defense-in-depth against XSS.
