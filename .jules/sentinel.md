## 2024-05-18 - CSP for Standalone Babel Applications
**Vulnerability:** Missing Content Security Policy (CSP) headers, allowing arbitrary external resource loading and potentially enabling Cross-Site Scripting (XSS).
**Learning:** Standalone React applications using Babel require `'unsafe-inline'` and `'unsafe-eval'` in the `script-src` directive of the CSP. Attempting to use a strict CSP without these will break the client-side compilation and rendering. In addition, when external resources like images and videos are loaded, the exact domains (and `data:`/`blob:` schemas if necessary) must be explicitly whitelisted in `img-src`, `media-src`, and `connect-src` to avoid falling back to restrictive policies.
**Prevention:** Always implement a baseline CSP in web applications. For Babel standalone apps, document the necessary `'unsafe-eval'` and `'unsafe-inline'` exceptions, and ensure any domain integrations (e.g., pollinations.ai, pexels, pixabay) are whitelisted explicitly in the relevant fetch directives.
